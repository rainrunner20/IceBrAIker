# Profile API contract

This change hardens the Flask HTTP boundary **without changing the existing profile-generation provider**. The old LangChain/LinkedIn path still requires provider credentials and may not work until its external integrations are modernized.

## Endpoints

| Method | Path | Response |
| --- | --- | --- |
| GET | `/health` | 200, `{"status":"ok"}` |
| POST | `/process` | 200, profile summary, topics, ice breakers, and optional picture URL |

Request:

```json
{"name":"Ada Lovelace"}
```

Success response shape (example generated by the offline test stub, not live profile data):

```json
{
  "summary_and_facts": {"summary":"Profile for Ada Lovelace", "facts":["Works in software"]},
  "interests": {"topics_of_interest":["Engineering"]},
  "ice_breakers": {"ice_breakers":["What are you building?"]},
  "picture_url": null
}
```

Error codes:

- **400:** malformed JSON, missing/invalid name, wrong JSON object shape.
- **413:** body exceeds 16 KiB.
- **415:** request is not JSON.
- **502:** upstream lookup or model generation failed (details are not returned to clients).

## Local contract checks

API tests do **not** call OpenAI, Tavily, Google, Proxycurl, or LinkedIn. They supply a stub via `create_app(processor=...)` to test the HTTP surface deterministically.

```powershell
cd flask-backend
python -m pip install -r requirements-api-test.txt
python -m unittest discover -s tests -v
```

For an actual provider-backed run, install the production requirements separately, configure the provider credentials locally, and start `python app.py`. No credentials should ever be committed.

Allowed browser origins default to `http://localhost:3000`. Set `ICEBRAIKER_ALLOWED_ORIGINS` to a comma-separated list of trusted frontend origins before deploying. CORS is a browser policy, **not authentication**.

## Production readiness gaps

- Provider integration still uses older APIs and unverified profile data sources.
- No authentication, per-user request limits, request budgets, cost controls or audit logging.
- No persisted profiles or evidence-backed retrieval pipeline yet; **PostgreSQL/RAG/DistilBERT claims are not verified by this milestone**.
- No full end-to-end deployment smoke test yet. The health check proves only that Flask responds.

These must be addressed before labeling IceBrAIker production-ready or claiming measured gains in matching quality.
